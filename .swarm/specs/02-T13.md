# 02 — T13 Move to tomorrow

## Goal
Add "Move to tomorrow" to a task's row menu and a bulk "Move unfinished to tomorrow" for today. Both reuse the existing `moveTaskToDay` semantics: task + its subtasks move, `updatedAt` is stamped so sync sees the edit.

## Files to change
- `src/domain/tasks.ts` — add pure `unfinishedTopLevelOn(tasks, date)` and `moveTasksToDay(tasks, ids, targetDate, now)`.
- `src/domain/tasks.test.ts` — NEW (tests).
- `src/state/store.tsx` — `moveTaskToDay(id, date)` delegates to the pure helper; add `moveUnfinishedToTomorrow(date): number` to `Actions` (import `addDays` from `domain/dates`).
- `src/components/TaskRow.tsx` — per-row `⋯` menu with "Move to tomorrow".
- `src/components/DayView.tsx` — bulk item in the existing "List menu", shown only when `selected === today`; toast the count via `useToast`.

## Data / API shape
`unfinishedTopLevelOn(tasks, date): Task[]` = tasks with `!deletedAt && !parentId && !done && date === target`, sorted by the file's existing `byOrder`.
`moveTasksToDay(tasks, ids, targetDate, now): { tasks: Task[]; moved: string[] }`:
- for each id, move that task and its live subtasks (`parentId === id && !deletedAt`) to `targetDate`;
- set `order = (max order among non-deleted tasks already on targetDate) + 1 + index` for each moved top-level task (subtasks keep their own `order`);
- stamp `updatedAt: now` on every moved row; keep `categoryId`, `done`, `seriesId`, `habitId`, note and `parentId` untouched;
- skip ids not found or already on `targetDate` (no `moved` entry). Pure: caller passes the ISO `now`; no `Date`/`uid` calls inside.
`store.moveUnfinishedToTomorrow(date)` selects ids via `unfinishedTopLevelOn(dataRef.current.tasks, date)`, calls the helper with `addDays(date, 1)` and `nowISO()`, commits with `update`, returns `moved.length`.

## Edge cases / must NOT change
- Done tasks, standalone subtasks, soft-deleted tasks and tasks on other days are never moved.
- A moved subtask follows its parent, so "2/5" subtask progress stays correct.
- Ghost habit suggestions are not tasks: never move or hide them.
- Recurring template tasks with `rrule` on today are top-level tasks — include them; their materialised occurrences are separate rows.
- Do NOT change `task-page/sync.ts`, the TaskPage date input, checkbox/toggle behaviour, or "Show completed" / "Hide empty categories" prefs.

## Tests (`src/domain/tasks.test.ts`, NEW)
- `unfinishedTopLevelOn` excludes done/subtask/deleted/other-day tasks and sorts by order.
- `moveTasksToDay` moves parent + live subtasks, appends order on the target day, stamps `updatedAt`, leaves note/category/done intact.
- Re-moving an id already on the target date is a no-op; a missing id is ignored.
