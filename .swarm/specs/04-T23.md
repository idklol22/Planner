# 04 — T23 Harden the /task slash command

## Goal
Keep the already-present `/task` slash item (case-insensitive, also `/Task`) that inserts a `taskItem` block bound to a real subtask, and make its matching/block shape unit-testable. No behaviour change intended.

## Files to change
- `src/components/task-page/slash.ts` — NEW, pure: `TASK_SLASH_TITLE = "Task"`, `taskSlashAliases`, `taskSlashItemMatches(query)`, `taskBlockProps(subtaskId)`.
- `src/components/task-page/slash.test.ts` — NEW (tests).
- `src/components/task-page/TaskPage.tsx` — import from `slash.ts`; the extra item in `withAfterBasic(getDefaultReactSlashMenuItems(editor), …)` uses those constants and `taskBlockProps(id)` in `insertOrUpdateBlockForSlashMenu`.

## Data / API shape
`taskSlashAliases = ["task", "todo", "subtask", "check"]`; item descriptor stays `{ title: "Task", aliases: taskSlashAliases, group: "Basic blocks", subtext: "A real subtask you can tick off", icon: <span>☒</span> }` (keep the current `&#9744;` icon).
`taskSlashItemMatches(query: string): boolean` — `const q = query.trim().replace(/^\/+/, ""); if (!q) return false; return filterSuggestionItems([descriptor], q).length > 0;` (`filterSuggestionItems` from `@blocknote/core/extensions` is already case-insensitive over title + aliases; the leading-slash strip makes `/task` work in tests as it does in the editor).
`taskBlockProps(subtaskId) => ({ type: "taskItem", props: { subtaskId, checked: false } })`.
`onItemClick` stays: `addSubtask(task.id, PLACEHOLDER_TITLE)` → set `optimistic` and `lastRef` → `insertOrUpdateBlockForSlashMenu(editor, taskBlockProps(id))`.

## UI/UX
- No visual change. The item keeps the ☐ icon, "Task" label and "A real subtask you can tick off" subtext in the "Basic blocks" group; BlockNote owns hover highlight, ↑/↓ + Enter and Escape.
- The inserted block renders via the existing `taskItemBlock` in `schema.tsx`: 22px ring checkbox on the left, inline title on the right, checked state from theme ink/accent tokens. Typing a title and ticking the box still syncs both ways through `planSync`.
- Keyboard: `/task` + Enter and `/Task` + Enter each create exactly one block and one real subtask; focus stays in the editor. Narrow screens: BlockNote already constrains the suggestion menu — do not add CSS.

## Edge cases / must NOT change
- A pasted `taskItem` block with no `subtaskId` still gets a fresh subtask (`planSync` already handles it).
- Deleting the block deletes the real subtask; deleting the subtask elsewhere removes the block — unchanged.
- Do NOT change `planSync`, `schema.tsx`, `PLACEHOLDER_TITLE` ("Untitled"), `markdown.ts`, the store's `addSubtask`, or any other slash-menu item.

## Tests (`src/components/task-page/slash.test.ts`, NEW)

- `taskBlockProps("s1")` equals `{ type: "taskItem", props: { subtaskId: "s1", checked: false } }`.
- Keep `task-page.test.ts` green (no edits needed there).
