# 03 — T09 Sync on tab hide / app close

## Goal
Keep the 60s autosync, and add best-effort pushes when the tab is hidden or the app closes: `visibilitychange`, `beforeunload`/`pagehide` with `keepalive`, and the Tauri close event. No Settings UI change.

## Files to change
- `src/storage/hub.ts` — add `HubClient.pushKeepalive(ops): boolean` (POST `/ops`, bearer header, `keepalive: true`).
- `src/sync/flush.ts` — NEW, pure `keepaliveBatch(ops, maxOps, maxBytes)`.
- `src/sync/flush.test.ts` — NEW (tests).
- `src/sync/controller.ts` — add optional `keepalive?(ops): boolean` to `SyncControllerOptions` and a `flush(): void` method.
- `src/state/store.tsx` — add `flush(): Promise<void>` to `StoreValue`: cancel the 250ms debounce, `await storage.save(dataRef.current)`.
- `src/state/sync.tsx` — wire the listeners; expose `flush()` in `SyncContextValue`.

## Data / API shape
`SyncController.flush()` reads `outbox.pending(...)`, passes ops through `keepaliveBatch`, and calls `options.keepalive(batch)` if present. It MUST NOT ack ops (a response cannot be awaited during unload; hub upserts are idempotent on `updatedAt`) and MUST NOT emit status changes.
`HubClient.pushKeepalive(ops)` builds the `{ ops }` JSON body, returns `false` when body length > 60,000 bytes or `navigator`/`fetch` is missing, otherwise fires `fetch(`${base}/ops`, { method: "POST", headers: { Authorization: `Bearer ${token}`, "Content-Type": "application/json" }, body, keepalive: true }).catch(() => {})` and returns `true`. Use `fetch`, not `sendBeacon` — the hub needs the auth header. Caller constants: 40 ops / 60,000 bytes.
`keepaliveBatch(ops, maxOps, maxBytes)` returns the longest prefix of `ops` whose `JSON.stringify({ ops: prefix }).length <= maxBytes`, capped at `maxOps`, never splitting an op.

## Trigger wiring (`src/state/sync.tsx`)
- Keep `controller.start(SYNC_INTERVAL_MS)` (60s) and the existing `visibilitychange` → `syncNow()` kick exactly as-is.
- Add one provider-lifetime effect with a stable `flushRef` that calls `store.flush()` then `controllerRef.current?.flush()`:
  - `document.addEventListener("visibilitychange", () => { if (document.visibilityState === "hidden") flushRef.current(); })`.
  - `window.addEventListener("pagehide", flushRef.current)` and `window.addEventListener("beforeunload", flushRef.current)`.
  - Tauri only (`isTauri` from `../storage`): `const { getCurrentWindow } = await import("@tauri-apps/api/window"); const unlisten = await getCurrentWindow().onCloseRequested(async (event) => { event.preventDefault(); flushRef.current(); await new Promise((r) => setTimeout(r, 300)); await getCurrentWindow().destroy(); });` — use `destroy()` (not `close()`) to avoid re-entering `onCloseRequested`.
  - Cleanup removes all DOM listeners and calls `unlisten()`.
- `syncNow()` and `sendNote()` semantics unchanged. The controller's `keepalive` option is passed from `sync.tsx` as `(ops) => client.pushKeepalive(ops)`.

## Edge cases / must NOT change
- No hub configured or empty outbox → all flushes are no-ops; do not touch localStorage or the DOM.
- Offline / fire-and-forget failure leaves ops in the outbox for the next 60s/online sync. Never ack or delete them on flush.
- Large outbox: only the first ≤40 op / ≤60 KB batch is sent; the rest waits for normal sync.
- Mirror tables (`h_*`) are never pushed.
- Node/SSR (no `navigator`) → `pushKeepalive` returns `false` without throwing.
- Do NOT change `SYNC_INTERVAL_MS`, `PUSH_DEBOUNCE_MS`, `SyncEngine`, hub auth/row shapes, or `lastSyncedAt`. No toast for background flushes.

## Tests (`src/sync/flush.test.ts`, NEW)
- `keepaliveBatch` respects `maxOps`, respects `maxBytes` against the exact `{ ops }` body, returns `[]` for empty input, and never splits an op.
- Existing `src/sync/controller.test.ts` and `src/sync/sync.test.ts` stay green.
